# Productive — Product & Technical Plan (v1)

Owner: planner. Audience: designer, coder, reviewer. The coder should follow this spec literally; anything not covered is a judgement call to keep minimal.

---

## 1. Product summary

**Productive** is a single-user, local-first study tracker that works like Strava crossed with a consultant's timesheet. Every minute of study is a **time entry** billed against a **course** (the "client") and usually a **section** (the "project/task"). The student works through their material **one section per day**, aims for a **daily goal (default 8h)**, plans each week's **time blocks** and **weekly goals** on Monday, and reviews the results on Sunday. All data lives in the browser with JSON export/import for backup.

### Core loop

1. **Monday — Plan Week.** Set the week's goals (pre-filled from defaults), assign one section to each day (auto-assign suggests the next unfinished sections), and lay out time blocks on a week grid (or copy last week's blocks).
2. **Every day — Today.** Open the app, see today's section and planned blocks, press **Clock in** (Space). Clock out when done or switch section. Watch the ring fill towards 8h. Mark the section done when finished; unfinished sections can be carried to the next day.
3. **Any time — Timecard.** See the week as a timesheet (courses × days), fix or add entries by hand.
4. **Sunday — Review.** See which goals were met, planned vs actual, streak, heatmap, trends; write a short reflection. Then plan next week.

## 2. Domain model

All types live in `src/domain/types.ts`. Conventions:

- **IDs:** `string`, generated by `newId()` = `crypto.randomUUID()` (fallback: `Date.now().toString(36) + Math.random().toString(36).slice(2)`).
- **Instants** (`IsoInstant`): full UTC ISO strings from `Date.prototype.toISOString()`, e.g. `"2026-10-26T14:03:00.000Z"`.
- **Local calendar days** (`DateKey`): `"YYYY-MM-DD"` in the user's **local** time zone. All "which day/week does this belong to" logic uses local time.
- **Week key** (`WeekKey`): the `DateKey` of the week's Monday.
- **Durations:** integer **minutes** in storage and logic. Hours only appear in the UI (formatted `7h 45m` or `7.75h` in Timecard).
- **Weekday index:** `0 = Monday … 6 = Sunday`.

```ts
export type Id = string;
export type IsoInstant = string;   // "2026-10-26T14:03:00.000Z"
export type DateKey = string;      // "2026-10-26" (local)
export type WeekKey = DateKey;     // always a Monday
export type Weekday = 0 | 1 | 2 | 3 | 4 | 5 | 6; // Mon..Sun

export interface Course {
  id: Id;
  name: string;            // "Organic Chemistry"
  color: string;           // one of COURSE_COLORS (8 fixed hex values in domain/colors.ts)
  archived: boolean;       // archived courses are hidden from pickers but kept in history
  createdAt: IsoInstant;
}

export interface Section {
  id: Id;
  courseId: Id;
  title: string;                   // "Ch 4 – Stereochemistry"
  order: number;                   // 0-based position within course; contiguous after any reorder/delete
  estimatedMinutes: number | null; // optional estimate, used for a progress bar only
  completedAt: IsoInstant | null;  // non-null === done
  notes: string;                   // free text, default ""
}
// Derived (never stored): status = completedAt ? 'done' : loggedMinutes > 0 ? 'in_progress' : 'todo'
export type SectionStatus = 'todo' | 'in_progress' | 'done';

export interface TimeEntry {
  id: Id;
  courseId: Id;              // required — every minute bills to a course
  sectionId: Id | null;      // optional — null = general work on the course
  start: IsoInstant;
  end: IsoInstant;           // end > start, end <= now, (end - start) <= 16h
  note: string;              // default ""
  source: 'timer' | 'manual';
  createdAt: IsoInstant;
  updatedAt: IsoInstant;
}

export interface ActiveTimer {
  courseId: Id;
  sectionId: Id | null;
  startedAt: IsoInstant;
  note: string;
}

export interface ScheduledBlock {
  id: Id;
  date: DateKey;             // must fall within its WeekPlan's week
  startMin: number;          // minutes after local midnight, multiple of 15
  endMin: number;            // > startMin, <= 1440, multiple of 15
  courseId: Id;
  sectionId: Id | null;
  label: string;             // optional display text, default ""
}

export type Goal =
  | { id: Id; kind: 'totalHours'; targetMinutes: number }
  | { id: Id; kind: 'courseHours'; courseId: Id; targetMinutes: number }
  | { id: Id; kind: 'sectionsCompleted'; courseId: Id | null; targetCount: number } // null = any course
  | { id: Id; kind: 'dailyGoalDays'; targetCount: number };

export interface WeekPlan {
  weekStart: WeekKey;
  dailyGoalMinutes: number;               // snapshot of settings at creation; editable on Plan page
  restDays: Weekday[];                    // snapshot of settings at creation; editable on Plan page
  goals: Goal[];
  sectionByDay: Record<DateKey, Id | null>; // exactly the 7 dates of the week as keys
  blocks: ScheduledBlock[];
  reviewNote: string;                     // end-of-week reflection, default ""
  createdAt: IsoInstant;
  updatedAt: IsoInstant;
}

export interface Settings {
  dailyGoalMinutes: number;   // default 480
  restDays: Weekday[];        // default [] (user can pick e.g. [6] for Sunday)
  gridStartHour: number;      // default 6  (week grid visible range)
  gridEndHour: number;        // default 24
  onboarded: boolean;         // default false
}

export interface AppData {
  schemaVersion: 1;
  settings: Settings;
  courses: Course[];
  sections: Section[];
  entries: TimeEntry[];
  weekPlans: Record<WeekKey, WeekPlan>;
  activeTimer: ActiveTimer | null;
}

export interface GoalProgress {
  goalId: Id;
  current: number;          // minutes or count, same unit as target
  target: number;
  ratio: number;            // current / target, clamped to [0, 1] for display
  status: 'met' | 'on_track' | 'behind' | 'missed';
}
```

### Midnight and day attribution

- A time entry is stored **as one record**, even if it spans midnight (e.g. 23:10–01:20).
- All per-day aggregation goes through one function, `splitByLocalDay(start, end): Array<{ date: DateKey; minutes: number }>`, which cuts the interval at each local midnight. The 23:10–01:20 entry contributes 50 min to day 1 and 80 min to day 2. Week totals likewise use the per-day pieces, so an entry spanning Sunday→Monday is split across two weeks.
- The **running timer** is treated as a virtual entry `[startedAt, now]` and passed through the same function, so after midnight the Today ring starts from the post-midnight portion only.
- Minutes are computed as `Math.round(ms / 60000)` per piece. DST is handled naturally because pieces are cut at real local midnights (`new Date(y, m, d)`), never by adding 24h.
- Timeline views (Today, Timecard detail) show a cross-midnight entry on both days, clipped to that day, with a "↪ continues" marker.

### Storage choice

**localStorage**, single key `productive:v1` holding the serialized `AppData`. Justification: a heavy year is ~4,000 entries × ~250 bytes ≈ 1 MB, well under the ~5 MB quota; synchronous reads let the app load state before first render with no async loading states; export/import is trivially the same JSON. Access is behind a `Storage` interface (section 6) so moving to IndexedDB later is a one-file change. If a write throws `QuotaExceededError`, show a persistent error banner telling the user to export a backup.

## 3. Screens and routes

Hash router (`createHashRouter` / `HashRouter` from `react-router-dom@6`). Vite `base: './'`. Navigation: left sidebar at ≥ 720px width, bottom tab bar below 720px. Nav items: Today, Plan, Timecard, Courses, Review, Settings. The running timer is shown as a compact pill in the nav (course colour dot + elapsed `1:23:45` + stop button) on every page except Today.

| Route | Page |
|---|---|
| `#/` | Today |
| `#/plan` and `#/plan/:weekStart` | Plan Week (no param = current week) |
| `#/timecard` and `#/timecard/:weekStart` | Timecard |
| `#/courses` | Courses list |
| `#/courses/:courseId` | Course detail (sections) |
| `#/review` and `#/review/:weekStart` | Review & Insights (no param = current week) |
| `#/settings` | Settings |
| `#/welcome` | First-run onboarding |

Any `:weekStart` that is not a Monday is normalised to its Monday via `replace` navigation. Unknown routes redirect to `#/`. If `settings.onboarded === false` and there are no courses, `#/` redirects to `#/welcome`.

### 3.1 Today (`#/`)
**Purpose:** clock in/out and see how today is going.
**Contents (desktop: two columns; mobile: stacked in this order):**
1. **Timer card.** Big elapsed time (`H:MM:SS`), course + section pickers (default: today's assigned section and its course), note field, **Clock in / Clock out** button, **Switch** button (visible while running: opens picker; confirming stops current entry and starts a new one at the same instant).
2. **Progress ring:** today's minutes vs `dailyGoalMinutes` (from this week's plan, else settings), centre text `5h 20m / 8h`, sub-text "2h 40m to go" or "Goal hit ✓". On a rest day the ring shows minutes with label "Rest day".
3. **Today's section card:** section title, course, logged minutes on this section (all time) vs estimate as a bar, **Mark done** button. If none assigned: "No section assigned today" + link to Plan.
4. **Carry-over banner** (see 4.3) when applicable.
5. **Day timeline:** vertical strip `gridStartHour–gridEndHour`; planned blocks as outlined boxes, actual entries as filled bars in course colours, side by side; a "now" line. Below it: "Planned 6h 00m · Actual 5h 20m · Adherence 78%".
6. **Today's entries list:** time range, course/section, duration, note; edit/delete via the shared Entry dialog; "+ Add entry" button.
7. **Week strip:** Mon–Sun mini bars of minutes vs goal, streak badge ("🔥 12 days" text, no emoji required — designer's choice).

**Banners:** "No plan for this week — Plan it" (link) if `weekPlans[currentWeek]` is missing. "Timer has been running 10h+ — still studying?" with "Stop at last activity…" (opens Entry dialog prefilled so the user can set the real end) when the active timer exceeds 10h.

### 3.2 Plan Week (`#/plan/:weekStart`)
**Purpose:** Monday planning. A **single scrollable page** with three panels (no wizard). Header: week navigation (‹ prev · "Week of 26 Oct 2026" · next ›, "This week" button). Opening a week with no plan **creates it immediately** with defaults (see 4.1); past weeks are editable too (no lock).

1. **Goals panel.** Daily goal input (hours, step 0.25) and rest-day toggles (Mon–Sun chips) for this week. List of goals; each row = kind select, target input, course select where relevant, delete. "+ Add goal". Kinds shown as: "Total hours", "Hours on a course", "Sections completed", "Days hitting daily goal".
2. **Sections panel.** Seven rows (Mon–Sun, date shown; rest days greyed but still assignable). Each row: a select of all not-done sections grouped by course (in course order, then section order), plus the currently assigned one even if done (shown with ✓). Buttons: **Auto-assign** (fill empty non-rest days from today onward — or from Monday when planning a future week — with the next unfinished, unassigned sections of the chosen course; course chosen via a small select, defaults to the course with the most remaining sections), **Clear**.
3. **Schedule panel (week grid).** 7 day columns × 15-minute rows from `gridStartHour` to `gridEndHour`, 1 hour ≈ 48px. Header row shows each day's planned total; panel footer shows the week's planned total vs `dailyGoalMinutes × non-rest days`.
   - **Create:** pointer-down on empty space and drag vertically → creates a block snapped to 15 min (min 15 min). Plain click creates a 60-minute block. New block defaults to that day's assigned section (and its course), else the last-used course.
   - **Edit:** click a block → popover with course, section, label, start/end time inputs, Delete.
   - **Move/resize:** drag block body to move (within and across days); drag bottom edge to resize. Pointer events only, no library. Blocks may not overlap within a day — on conflicting drop, snap back.
   - **Copy last week's blocks:** replaces this week's blocks with the previous week's shifted +7 days (confirm if blocks exist). A separate **Copy last week's goals** button (in the Goals panel) replaces this week's goals with copies (new ids) of the previous week's (confirm if goals were edited).
   - **Mobile (< 720px):** show one day at a time with day tabs; no drag — "+ Add block" opens the same popover as a form.

### 3.3 Timecard (`#/timecard/:weekStart`)
**Purpose:** timesheet view of the week, consultant style.
- **Grid:** rows = courses that have entries this week (plus an "+ Add row" picker to add another course), expandable to section sub-rows (including a "General" sub-row for `sectionId: null`). Columns Mon–Sun + **Total**. Cells show decimal hours (`2.50`), blank when zero. Footer row = daily totals, with each day's total coloured green when ≥ that day's goal. Bottom-right = week total.
- **Cell click** → side panel (bottom sheet on mobile) listing that course/section's entries for that day, each editable/deletable, plus "+ Add entry" prefilled with that day and course/section.
- **Summary card ("Statement"):** week total hours, per-course line items with hours and % of week, sections completed this week, days goal hit. **Export CSV** button (columns: `date,start,end,minutes,course,section,note,source`) and **Print** button (print stylesheet shows only the grid + summary).
- Week navigation identical to Plan.

### 3.4 Courses (`#/courses`) and Course detail (`#/courses/:courseId`)
**Courses list:** cards per active course: colour, name, sections done / total, total hours logged, progress bar (done/total). "+ New course" (name, colour). "Show archived" toggle.
**Course detail:** editable name/colour; Archive / Delete (delete only allowed when the course has no entries, otherwise only archive). Section list in order: checkbox (done/undone), title (inline editable), estimate (hours), logged hours, status chip, ↑/↓ reorder buttons, delete. "+ Add section" single input, and **"Add many"**: a textarea, one section per line, optional `| hours` suffix (`Ch 5 – Kinetics | 6`). Empty state: "No sections yet — paste your table of contents."

### 3.5 Review & Insights (`#/review/:weekStart`)
**Purpose:** end-of-week review plus long-term trends. Week navigation in header.
- **Goal results:** each goal with progress bar, `current / target`, status chip (met / on track / behind / missed).
- **This week by day:** bar chart Mon–Sun of actual minutes with a goal line; planned minutes as a ghost bar behind each actual bar.
- **Sections:** planned (from `sectionByDay`) vs completed this week, as a list with ✓/✗ and "carried" markers.
- **Course breakdown:** horizontal bars of minutes per course this week.
- **Reflection:** textarea bound to `reviewNote` (autosave).
- **Insights (not week-scoped):** current streak and best streak; **26-week heatmap** (columns = weeks Mon-start, rows = Mon–Sun, 5 intensity levels); **weekly totals for the last 12 weeks** bar chart; all-time total hours.
- All charts are hand-rolled SVG components; no chart library.

### 3.6 Settings (`#/settings`)
Daily goal (hours, default 8), default rest days, grid start/end hour, **Export JSON** (downloads `productive-backup-YYYY-MM-DD.json`), **Import JSON** (file picker → validate → confirm "This replaces all current data" → replace), **Reset all data** (type `RESET` to confirm; returns to `#/welcome`). Show storage usage (`~312 KB`). Note: changing the daily goal/rest days affects the current and future weeks' defaults only for weeks not yet created; the current week's plan is updated too if it exists (prompt: "Also apply to this week?").

### 3.7 Welcome (`#/welcome`)
Three steps on one page, each a card revealed in turn (see 4.8). "Skip" link on every step → marks onboarded and goes to Today.

### Shared components
- **Entry dialog** (add/edit): date, start time, end time (end may be next day via "ends next day" checkbox), course, section, note. Shows duration live. Validation errors inline (see 4.6). Delete button in edit mode.
- **Confirm dialog**, **Toast** (bottom, 4s, used for "Entry saved", "Timer under 1 min discarded", undo for deletes).
- **Undo:** deleting an entry, block or section shows a toast with **Undo** (restores the exact object).

### Out of scope for v1
Accounts, cloud sync, multi-device; notifications/reminders; Pomodoro mode; hourly rates/invoices/money; calendar (Google/ICS) integration; recurring block rules beyond "copy last week"; tags; multiple sections per day as a planning concept (entries can still go to any section); drag-and-drop on touch devices; PWA/installable offline mode; importing the old "Eight Hours" prototype data; theme switcher (dark mode follows `prefers-color-scheme` via CSS variables only); i18n (use `Intl` formatting with the browser locale, English UI strings).

## 4. Behaviour rules

All rules below are pure functions in `src/domain/` and must be unit-tested.

### 4.1 Week plans
- `weekStartOf(date: DateKey): WeekKey` returns the Monday on or before `date`. `weekDates(weekStart)` returns the 7 `DateKey`s.
- `createWeekPlan(weekStart, settings, now)` returns: `dailyGoalMinutes` and `restDays` from settings; `sectionByDay` with all 7 dates → `null`; `blocks: []`; `reviewNote: ""`; default goals:
  1. `totalHours` with `targetMinutes = dailyGoalMinutes × (7 − restDays.length)`
  2. `dailyGoalDays` with `targetCount = 7 − restDays.length`
- A day's goal: `dailyGoalFor(date, data)` = plan for that week's `dailyGoalMinutes` if the plan exists, else `settings.dailyGoalMinutes`. Rest days likewise. This keeps history stable when settings change.

### 4.2 Goal progress (`computeGoalProgress(goal, plan, data, now)`)
Measured over the plan's 7 dates, using minutes from `splitByLocalDay` (running timer included up to `now`).
- **totalHours:** `current` = sum of all entry minutes within the week.
- **courseHours:** `current` = sum of minutes of entries with `courseId === goal.courseId` within the week.
- **sectionsCompleted:** `current` = number of sections (filtered by `courseId` unless null) whose `completedAt` falls on a local date within the week. Un-marking a section removes it.
- **dailyGoalDays:** `current` = number of dates in the week (rest days included — studying on a rest day counts) where that day's minutes ≥ the week's `dailyGoalMinutes`.

**Status:**
- `met` if `current ≥ target`.
- Else if the week has ended (now's local date > Sunday): `missed`.
- Else for `dailyGoalDays` only: `missed` if `current + remainingDays < target`, where `remainingDays` = dates ≥ today in the week.
- Else **pace**: `elapsed` = number of non-rest dates in the week strictly before today; `total` = non-rest dates in the week (min 1). `expected = target × elapsed / total`. `on_track` if `current ≥ expected`, else `behind`. (On Monday, `expected = 0`, so everything is on track.) For a future week everything is `on_track`.

### 4.3 Sections: done, and carry-over
- **Done = the user ticks it.** `completedAt = now`. Logged time never auto-completes a section; exceeding the estimate only turns the estimate bar amber. Un-ticking sets `completedAt = null`.
- Marking a section done from Today with time on the timer running against it does not stop the timer.
- **Carry-over:** when Today loads, let `Y` = the most recent date before today in the current week *or* the previous week whose `sectionByDay` is non-null (look back up to 7 days, skipping null days). If `Y`'s section is **not done** and it is **not** already assigned to today or any later day this week, show the banner: *"‘Ch 4’ (planned for Thu) isn't finished."* with three actions:
  1. **Do it today (shift plan):** `shiftPlanFrom(today)` — today gets the unfinished section; each previously assigned section from today onward moves to the next non-rest day; whatever falls off Sunday becomes unassigned (toast: "‘Ch 9’ moved off this week").
  2. **Mark done** — sets `completedAt`.
  3. **Dismiss** — store the dismissal in memory for this session only (`sessionStorage` key `productive:dismissed:<sectionId>:<date>`); no data change.
- Nothing rolls over automatically; the user always chooses.

### 4.4 Streaks (`computeStreaks(data, today)`)
- A date is **hit** if its minutes ≥ `dailyGoalFor(date)`.
- **Current streak:** walk backwards starting at *yesterday*. For each date: if hit → +1; else if it is a rest day → skip (neither breaks nor counts); else stop. Then if *today* is hit, +1. (So an unfinished today never breaks the streak.) Stop at the date of the earliest entry.
- **Best streak:** the maximum run over all history with the same rest-day rule.
- A hit rest day counts +1.

### 4.5 Planned vs actual
- **Planned minutes (day)** = sum of `endMin − startMin` of that day's blocks.
- **Actual minutes (day)** = minutes from `splitByLocalDay` for that date.
- **Adherence (day)** = Σ over blocks of `overlapMinutes(block, entries with same courseId)` ÷ planned minutes, as a %; shown as "—" when nothing is planned. Section is ignored for adherence (course match is enough).
- Week adherence = same sums across the week.

### 4.6 Time entry validation (`validateEntry(entry, data, now)`)
Reject with a message when: end ≤ start; end > now (+1 min tolerance); duration > 16h; course missing or archived (archived allowed only when editing an existing entry); section not in that course; **overlaps** another entry or the running timer interval (entries are a timesheet — no double billing). Entries may touch (one ends 10:00, next starts 10:00).

### 4.7 Timer
- **Clock in:** requires a course; sets `activeTimer` with `startedAt = now`. Only one timer at a time.
- **Clock out:** creates a `TimeEntry` (`source: 'timer'`) from `startedAt` to now. Store exact instants; minute rounding happens only in aggregation. If the duration is < 60 s, discard and toast "Under a minute — not logged".
- **Switch:** clock out + clock in at the same `now`.
- The timer survives reloads (persisted in `activeTimer`). Elapsed display ticks via a `useNow(1000)` hook only on components that need it.
- If clock-out would create an overlap (e.g. a manual entry was added inside the running interval), the entry's start is moved to the end of the latest overlapping entry; if nothing remains, discard with a toast.

### 4.8 First-run onboarding (`#/welcome`)
1. **Your goal:** daily goal (default 8h) and rest days. "Next".
2. **Your material:** course name + colour, then the "Add many" textarea for sections (one per line, optional `| hours`). Requires ≥ 1 course name; sections optional. "Next". (Text below: "You can add more courses later.")
3. **This week:** creates the current week's plan, runs Auto-assign from today for that course, shows the resulting day→section list (editable selects). Button **"Start studying"** → `onboarded = true`, go to `#/`.
Mid-week first run: days before today are left unassigned.

### 4.9 Empty states (each must exist)
- Today with no entries: ring at 0, "No time logged today. Press Space to clock in."
- Today with no courses: timer disabled, "Add a course to start tracking" → `#/courses`.
- Timecard empty week: "No time logged this week."
- Courses empty: "No courses yet" + New course button.
- Review with no data: charts render empty axes; goals list says "No goals set for this week — Plan it".
- Plan, no unfinished sections: sections panel shows "All sections are done — add more in Courses."

### 4.10 Persistence
- The store writes to storage **debounced 300 ms** after any change, and synchronously on `pagehide`.
- Listen to the `storage` event: if another tab writes `productive:v1`, replace in-memory state (last-writer-wins).
- **Import** validates with `validateAppData(unknown): AppData | string[]` (checks schemaVersion, required fields and types, referential integrity: entries/sections/blocks reference existing courses; dangling `sectionId`s are set to null with a warning). Invalid file → list errors, no change.
- **Deleting a section** with entries: confirm, entries keep `courseId` with `sectionId = null`; remove it from any `sectionByDay` and blocks (`sectionId = null`). Reorder remaining sections contiguously.

## 5. Keyboard shortcuts

Global handler in `useHotkeys`. Ignored when focus is in an `input`, `textarea`, `select`, or `[contenteditable]`, or when a dialog is open (except `Esc`).

| Key | Action |
|---|---|
| `Space` | Clock in (with today's defaults) / clock out — works on every page |
| `S` | Switch section (opens picker; only while running) |
| `N` | New manual entry (Entry dialog) |
| `D` | Mark today's section done (Today page) |
| `1`–`6` | Go to Today, Plan, Timecard, Courses, Review, Settings |
| `[` / `]` | Previous / next week (Plan, Timecard, Review) |
| `T` | Jump to this week / today |
| `?` | Show shortcuts overlay |
| `Esc` | Close dialog / popover / overlay |

`Space` must `preventDefault()` to avoid page scroll and must not fire when a `button` has focus (let the button handle it).

### State management
**React context + `useReducer`** (zero extra deps). One `AppData` state object. `StoreProvider` loads synchronously from storage in the `useReducer` initializer, then persists on change (4.10). Components read with `useStore()` and derive via selectors (wrap expensive ones in `useMemo`). The reducer is pure and receives `now` inside actions (never calls `Date.now()` itself) so it is testable.

```ts
export type Action =
  | { type: 'settings/update'; patch: Partial<Settings> }
  | { type: 'course/add'; course: Course }
  | { type: 'course/update'; id: Id; patch: Partial<Omit<Course, 'id'>> }
  | { type: 'course/delete'; id: Id }                       // reducer no-ops if entries exist
  | { type: 'section/addMany'; sections: Section[] }
  | { type: 'section/update'; id: Id; patch: Partial<Omit<Section, 'id' | 'courseId'>> }
  | { type: 'section/move'; id: Id; direction: -1 | 1 }
  | { type: 'section/delete'; id: Id }
  | { type: 'section/setDone'; id: Id; done: boolean; now: IsoInstant }
  | { type: 'entry/add'; entry: TimeEntry }
  | { type: 'entry/update'; entry: TimeEntry }
  | { type: 'entry/delete'; id: Id }
  | { type: 'timer/start'; timer: ActiveTimer }
  | { type: 'timer/stop'; now: IsoInstant; newEntryId: Id } // creates entry per 4.7
  | { type: 'timer/switch'; now: IsoInstant; newEntryId: Id; next: Omit<ActiveTimer, 'startedAt'> }
  | { type: 'plan/ensure'; weekStart: WeekKey; now: IsoInstant }
  | { type: 'plan/update'; weekStart: WeekKey; patch: Partial<Omit<WeekPlan, 'weekStart'>>; now: IsoInstant }
  | { type: 'plan/assignSection'; weekStart: WeekKey; date: DateKey; sectionId: Id | null }
  | { type: 'plan/shiftFrom'; date: DateKey; sectionId: Id }
  | { type: 'block/upsert'; weekStart: WeekKey; block: ScheduledBlock }
  | { type: 'block/delete'; weekStart: WeekKey; id: Id }
  | { type: 'data/replace'; data: AppData };                // import, reset, undo-restore, cross-tab sync
```

Validation (`validateEntry`, block overlap) happens in the UI **before** dispatch so errors can be shown; the reducer trusts its input except where noted.

### Storage interface

```ts
export interface Storage {
  load(): AppData | null;          // null = nothing stored or unparseable (log + start fresh, keep raw copy under 'productive:v1:corrupt')
  save(data: AppData): void;       // throws on quota errors; store catches and shows banner
  clear(): void;
  subscribe(onExternalChange: (data: AppData) => void): () => void; // cross-tab 'storage' event
  approxBytes(): number;
}
```

`exportJson(data)` / `importJson(text)` live in `storage/` as helpers wrapping `JSON.stringify(data, null, 2)` and `validateAppData`. Schema migrations: `schemaVersion` is checked on load; future versions add `migrate(raw): AppData`.
